# RCA — Blank `/kewalbansing/admin/overview` op productie (vastgoed-app)

## Conclusie (concrete oorzaak)
De pagina is NIET leeg door een missende slug, missende env var, of een verkeerde/mislukte deploy. De oorzaak is een **`500 Internal Server Error` op `GET /api/invoices`**, veroorzaakt door **één corrupt invoice-document** in de productie-DB dat verplichte velden mist. FastAPI valideert de *hele* lijst tegen het `response_model`; één ongeldig document laat de complete response falen → de Overzicht-pagina krijgt geen data en rendert blanco.

Dit reproduceert niet op preview omdat het betreffende document daar niet bestaat — het is puur een **data-shape probleem in productie**, niet een code-compile of build probleem.

## Bewijs (uit productie, run 71eeda25-625f-493a-ac95-6c7be689062c)

### 1. Backend log — de daadwerkelijke fout
```

fastapi.exceptions.ResponseValidationError: 3 validation errors:
  {'type': 'missing', 'loc': ('response', 0, 'period_year'),   'msg': 'Field required', ...}
  {'type': 'missing', 'loc': ('response', 0, 'period_month'),  'msg': 'Field required', ...}
  {'type': 'missing', 'loc': ('response', 0, 'invoice_number'),'msg': 'Field required', ...}
```
Het falende document:
```
id:          f8eea76b-b5f3-4163-ac87-3f122b24e723
company_id:  e485dfb7-d865-4310-9005-805125a38326  (kewalbansing)
```

Ontbrekende velden: `period_year`, `period_month`, `invoice_number`. Dit is een **borg/deposit** regel — die kent geen periode of factuurnummer, maar het `response_model` markeert die velden als verplicht (`Field required`, geen default/Optional).

### 2. Kwantificering (mongo_query, collection `invoices`)
- Totaal facturen voor deze company: **33**
- Facturen zonder `invoice_number`: **1**

→ 1 kapot document van de 33 blokkeert de **volledige** `/api/invoices` respons. Klassiek "poison record".

### 3. Uitgesloten hypotheses (jouw vragen 3/4/5)
- **Slug/DB (vraag 3):** `companies.slug = "kewalbansing"` BESTAAT in productie, `billing_status: "active"`, `id e485dfb7-...`. Apartments/tenants aanwezig (tenant_id/apartment_id in de invoice resolven). → NIET de oorzaak.
- **Deploy-status (vraag 4):** Meest recente run `71eeda25` (redeploy, success, klaar 2026-09-02 18:04:15Z) IS de actieve image. Geen build-fout, niets gesuppresst. → NIET de oorzaak.
- **Env vars (vraag 5):** `MONGO_URL`, `DB_NAME`, `EMERGENT_LLM_KEY` gezet en niet-leeg. Let op: er is **geen `APP_URL` key** — dit project gebruikt `APP_PUBLIC_URL` + `APP_PUBLIC_HOST` (beide gezet, niet-leeg). Enige lege key is `MOPE_API_KEY` (irrelevant voor overview). → NIET de oorzaak.
- **Browser/JS crash (vraag 2):** de blanco pagina is downstream-gevolg van de API-500, niet een production-only minified JS crash. De frontend krijgt een 500 op de facturen-fetch en de tab rendert geen inhoud.
- **Jouw recente wijzigingen** (`/api/public/{slug}/landing`, `/api/public/{slug}/login`, `ApiIntegration.jsx`) zijn NIET betrokken. De trigger is een borg-invoice die op 2026-09-02 16:19 via het AI-assistent pad is aangemaakt zonder factuurnummer/periode.

## De fix (kies één — aanrader: A + B)

**A. Robuustheid in code (voorkomt herhaling — sterk aanbevolen).**
In de invoice Pydantic response-model velden die niet voor elk facturtype bestaan optioneel maken met een default:
```python
class Invoice(BaseModel):
    invoice_number: Optional[str] = None
    period_year:  Optional[int] = None
    period_month: Optional[int] = None
    ...
```
Zoek in `backend/server.py` het `response_model` van de `GET /api/invoices` route en het bijbehorende model. Borg/deposit-regels (`category == "borg"`) horen geen verplichte `period_*`/`invoice_number` te hebben. Overweeg ook `List[Invoice]` serialisatie te ontkoppelen van één bad record (per-item try/except of `model_validate` met skip), zodat één corrupt document nooit de hele lijst sloopt.

**B. Data-herstel (directe fix voor de klant).**
Vul het ontbrekende veld voor het bestaande document, of genereer een factuurnummer voor borg-regels:
```
invoices._id = 6...  (id f8eea76b-b5f3-4163-ac87-3f122b24e723)
zet: invoice_number (bijv. "BORG-2026-0001"), period_year=2026, period_month=9
```
(Kan via DB Manager in de Deployment-panel of via een migratie-script over alle `category:"borg"` documenten zonder deze velden.)

**C. Aan de bron (AI-assistent invoice-creatie).**
Het pad `source: ai_assistant` dat borg-invoices aanmaakt vult `invoice_number`/`period_*` niet. Als code-fix A niet volstaat, laat dat creatiepad altijd een `invoice_number` zetten (of expliciet `None` toegestaan maken).

## Aanbeveling
Pas **A** toe (model velden Optional + defensieve serialisatie) — dit is de echte root-cause fix: één slecht record mag nooit een lijst-endpoint 500'en. Voer **B** uit om de klant nu te ontzorgen. Deploy daarna opnieuw.

## Scope-noot
Gediagnosticeerd uit productie-logs + read-only mongo_query; NIET gereproduceerd in een eph-sandbox (vereist de live productie-DB, die de sandbox niet heeft). De fix is data-/code-afhankelijk en hoort in de source-omgeving thuis.
