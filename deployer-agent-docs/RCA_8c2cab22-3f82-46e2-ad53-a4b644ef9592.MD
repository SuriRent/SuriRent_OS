# RCA — Deploy run 8c2cab22-3f82-46e2-ad53-a4b644ef9592 (vastgoed-app)

## Outcome
Build failed at step `build_image` → Cloud Build step #8 `frontend-build-push`. This is a **source-code** failure (frontend ESLint), not a manifest/infra issue. A fix is required in the app source and must be applied by the source-owning agent (E1), then the deploy re-triggered.

## Failure
`craco build` (react-scripts 5.0.1) exited non-zero with:

```
Step #8 - "frontend-build-push": Failed to compile.
[eslint]
src/pages/vastgoed/LoginPage.jsx
  Line 252:5:  Definition for rule 'react-hooks/exhaustive-deps' was not found  react-hooks/exhaustive-deps
error Command failed with exit code 1.
```

## Root cause
`frontend/src/pages/vastgoed/LoginPage.jsx` line 252 contains:

```js
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);
```

The `eslint-disable-next-line` comment names the rule `react-hooks/exhaustive-deps`, but that rule is **not registered** in this project's ESLint setup:
- `frontend/package.json` has no `eslintConfig` block and no `eslint-plugin-react-hooks` (nor `eslint`) dependency.
- There is no `.eslintrc*` file.
- `craco.config.js` only sets a webpack `@` alias; it does not add ESLint plugins.

When ESLint encounters an `eslint-disable` comment referencing a rule it cannot resolve, it raises a hard error, and CRA/react-scripts 5 fails the production build (`Failed to compile`). This is the SAME failure class the platform build script already works around for `src/index.js`: `build-frontend-artifacts.sh` (line ~53) strips a `@typescript-eslint/no-var-requires` reference for exactly this reason. LoginPage.jsx is a newer occurrence not covered by that patch.

This is why prior redeploys (21669e6c, fa0a0311, …) succeeded — they predate this LoginPage.jsx code.

## Fix (apply in source)
In `frontend/src/pages/vastgoed/LoginPage.jsx`, line 252, remove the unresolvable rule name from the disable comment:

```diff
-    // eslint-disable-next-line react-hooks/exhaustive-deps
+    // eslint-disable-next-line
```

A bare `// eslint-disable-next-line` preserves the author's intent (suppress lint on the next line) and works regardless of whether the `react-hooks` plugin is loaded. Removing the comment entirely also works (the rule isn't loaded to warn), but the bare form is safest.

This is the ONLY occurrence in the tree — `grep -rn 'react-hooks/exhaustive-deps' frontend/src` returns just this line.

### Optional durability improvement
To prevent recurrence, either add `eslint-plugin-react-hooks` + an `eslintConfig` extending `react-app` to `frontend/package.json`, or generalize the patch in `build-frontend-artifacts.sh` to also strip `react-hooks/exhaustive-deps` references. Not required for this deploy.
