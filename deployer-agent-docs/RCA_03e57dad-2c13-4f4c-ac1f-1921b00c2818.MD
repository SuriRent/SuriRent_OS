# RCA — Thermal receipt "BETAALD" font on Android APK

## Question
After the latest successful deploy, the Android APK still prints the paid amount
("BETAALD" + SRD bedrag) in a large font. Verify whether PRODUCTION is serving the
old or new backend code, and whether any edge cache could serve a stale print.html.

## Deployment under test
- Deployment: `vastgoed-app` (`app.surirent.sr` / https://vastgoed-app.emergent.host)
- Active (live) run: `03e57dad-2c13-4f4c-ac1f-1921b00c2818` — redeploy, status success, completed 2026-10-13T16:37:16Z
- Image: `...customers-app@sha256:d5047c8b...c60f2fb6`
- Template: fastapi_react_mongo_shadcn (farm), frontend_type=cloudflare

## Verdict: PRODUCTION IS SERVING THE LATEST (NEW) CODE. All three checks pass.

### (1) print.html — live HTTP fetch from the running prod backend
`GET /api/payments/4bf972ad-35eb-4aa7-aaed-ef8f712c6168/print.html?format=thermal&preview=1`
→ HTTP 200. The rendered BETAALD line is the **new** structure:
```
<div class="r"><span>BETAALD</span><span class="b">SRD 4.000,00</span></div>
```
- `paid-amt big` present in the served HTML? **False.** The old `paid-amt big` classes are gone.
- Corroborated in the deployed image's own source (`backend/server.py`, the archive built into the live image):
  - L11751: `<div class="r"><span>BETAALD</span><span class="b">{h(fmt_money(amount, currency))}</span></div>` (new)
  - (L11714 still defines a `.paid-amt { display:block; text-align:right; }` CSS rule, but it is no longer applied to the BETAALD line — harmless leftover, not the big font.)

### (2) print-data fontSizes.bedrag == tekst
`GET /api/kiosk/payments/{id}/print-data` over HTTP returns 401 `{"detail":"Kiosk niet ontgrendeld"}` (needs a kiosk unlock), so it can't be exercised anonymously. Verified instead in the deployed image source, `backend/server.py` L11383:
```
"fontSizes": {"tekst": _fs[0], "bedrijfsnaam": _fs[1], "kwitantie": _fs[2], "bedrag": _fs[0]}
```
`bedrag` is set to `_fs[0]`, the exact same value as `tekst`. **Confirmed equal** in production code.

### (3) Edge / CDN caching of print.html
Response headers from the live fetch:
- `Cache-Control: no-store`
- `CF-Cache-Status: DYNAMIC` (Cloudflare did NOT cache — routed to the k8s backend as dynamic)
- `Age`, `ETag`, `Via`: none
No Cloudflare edge cache is serving a stale print.html. `/api/*` is proxied to the backend and returned dynamic/no-store.

## Conclusion
The backend is fully updated and the server-rendered receipt is correct and NOT cached at
the edge. The persisting large "BETAALD" font on the APK is therefore **client-side**, not a
stale deployment or a CDN problem. Likely culprits on the Android side:
- The APK/WebView is reusing a **cached** copy of print.html and/or a cached print-data
  payload from before the deploy (despite server `no-store`, an in-app WebView/HTTP cache
  or a persisted print-data object can survive).
- The APK renders its own receipt template (bundled in the app) rather than the server HTML,
  so the font change in server.py never reaches it, OR it ignores `fontSizes.bedrag` and uses
  a hard-coded large size for the amount.
- The device is running an older APK build.

## Next steps (owned by E1 / app side — backend needs no change)
1. Inspect the APK's PRINT_RECEIPT path: does it render the fetched print.html verbatim, or
   build its own receipt from print-data? If it builds its own, that's where the big font lives.
2. If it uses print-data, confirm it reads `fontSizes.bedrag` for the amount (not a constant),
   and clear any persisted/cached print-data.
3. Clear the WebView/HTTP cache in the app (or reinstall/rebuild the APK) and reprint against
   a fresh payment to confirm.
