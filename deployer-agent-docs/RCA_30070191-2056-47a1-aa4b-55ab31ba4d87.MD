## (2) Identity comparison — what does KIOSK-ID equal?

### kiosk_printers (31 docs, all name "KT-V520[ #N]")
- `id` values are **UUIDv4** (e.g. `7bac180a-ce6c-4993-987c-66ba60ed0537`).
- **30 of 31 are `revoked: true`.** The ONLY non-revoked printer:
  - `id = 7bac180a-ce6c-4993-987c-66ba60ed0537`, name `"KT-V520"`, `revoked: false`, `last_seen: 0`, created 2026-10-17T11:32:50, company `a920fcef-0c04-48fc-8e05-19d6c3aeb2d6`.
- `last_seen` is `0` on essentially all rows (one revoked row `3a2ec15b…` has `1792191415.9`). So **no printer record has ever registered a live session** — consistent with the WS handshake always failing.

### kiosk_devices_seen where ua contains "V520" (12 docs)
- The identity field here is **`key` = 40-char hex** (e.g. `d8a21d1cb3260363561795c23ca89aa34f0be166`). There is no separate id field other than `_id` and `key`.
- Roles present: `printer`, `admin`, `employee`. Most recent `printer`-role entry: key `d8a21d1cb3260363561795c23ca89aa34f0be166`, name `"KT-V520"`, last_seen `2026-10-19T19:07:12`.
- UA for all 12: `Mozilla/5.0 (Linux; Android 11; V520 Build/RP1A.200720.011; wv) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/155.0.8059.43 Mobile Safari/537.36`.

### Verdict
`kiosk-1ecea20d9d0f` is:
- **NOT** a `kiosk_printers.id` (those are UUIDv4; this is `kiosk-`+12hex).
- **NOT** a `kiosk_devices_seen.key` (those are 40-char hex; `1ecea20d9d0f` is 12 hex and is not a prefix of any stored key).

→ It is a **third, device-local identifier — almost certainly an Android hardware ID (ANDROID_ID / serial), truncated/lowercased to 12 hex with a `kiosk-` prefix**. It is **"something else"** and it does **not map to any stored printer or device record**. So even if the backend tried to resolve the printer from the query param, there is no row keyed by this value.

## Root cause (printer-offline)
Two independent problems, both confirmed:

1. **Handshake mismatch.** The APK opens the socket with only `?device=kiosk-1ecea20d9d0f` and then sends only pings — it never sends the JSON auth frame that `@api.websocket("/kiosk/ws")` waits 10s for. The backend therefore closes with **4400** (observed directly after the device= connections). The printer never completes auth → shows offline.
2. **Identifier has no home.** The `kiosk-<androidid>` value the service sends matches **neither** `kiosk_printers.id` **nor** `kiosk_devices_seen.key`, and the only non-revoked printer (`7bac180a…`) has `last_seen: 0`. So there is currently no mapping that would let the backend associate this device with a printer row even if it read the query param.

## Suggested fixes (NOT applied — read-only)
- **Code (E1 / backend server.py ~10320):** make `/kiosk/ws` authenticate the printer from the `?device=` query param (and/or accept a ping-only keep-alive) instead of hard-requiring a JSON auth frame within 10s before closing 4400. Decide and implement the mapping `kiosk-<androidid>` → a `kiosk_printers` record. (Server-side; the Android APK is a separate client and is out of this platform's reach.)
- **User decision/data:** define what KIOSK-ID should map to. Today nearly every `kiosk_printers` row is `revoked: true`; only `7bac180a-ce6c-4993-987c-66ba60ed0537` ("KT-V520") is active. The device's `kiosk-1ecea20d9d0f` id must be associated with that (or a freshly provisioned, non-revoked) printer record, otherwise it stays offline even after the handshake is fixed.
