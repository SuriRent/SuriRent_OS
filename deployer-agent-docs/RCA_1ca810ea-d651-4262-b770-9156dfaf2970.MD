# RCA — Kiosk "Betalingsgeschiedenis" 500 on GET /api/kiosk/tenants/{id}/payments

## TL;DR
The latest hardening DID roll out to production — but the bug is in an **un-hardened code path**. `_company_brand_info()` returns **two** raw-bytes fields (`company_logo_bytes` AND `landlord_signature_bytes`). The hardening in `_enrich_payments_bulk()` strips only `company_logo_bytes`, leaving `landlord_signature_bytes` in the response. FastAPI's `jsonable_encoder` then does `.decode()` on that raw PNG during **response serialization (after the endpoint returns)**, raising `UnicodeDecodeError: 'utf-8' codec can't decode byte 0x9d in position 23`. Because it happens outside the endpoint body, the `TOP-LEVEL crash` try/except never fires and the fail-safe `return []` is never reached → HTTP 500.

## 4. Root cause (exact)
`backend/server.py`:
- `_company_brand_info()` (defined at line 8986→ returns dict) returns both:
  - `"company_logo_bytes": logo_bytes` (~line 8033)
  - `"landlord_signature_bytes": landlord_signature_bytes` (~line 8054)  ← **not stripped anywhere on the success path**
- `_enrich_payments_bulk()` line **8181**:
  ```python
  if b:
      b = {k: v for k, v in b.items() if k != "company_logo_bytes"}   # strips ONLY logo bytes
  ```
- Line ~8264 merges the brand dict into each row: `**(brand_cache.get(cid) or {})` → `landlord_signature_bytes` (raw PNG) enters the response.
- FastAPI response serialization calls `jsonable_encoder`, which for `bytes` does `value.decode()` (utf-8) → `UnicodeDecodeError` on the raw PNG → 500, outside the endpoint's try/except.

Why preview 13/13 passed and HUIS 7A fails: the reproduction requires a company with an uploaded **landlord signature** (`landlord_signature_url`). Gopi Appartements has one; the preview fixtures apparently did not, and prior hardening/tests targeted `company_logo_bytes` only.

## 5. The fix (verified in eph sandbox with the real FastAPI encoder)
Change `_enrich_payments_bulk()` line ~8181 to strip **all** bytes-typed values, not just the logo key:
```python
if b:
    b = {k: v for k, v in b.items() if not isinstance(v, (bytes, bytearray))}
```
This removes `company_logo_bytes` AND `landlord_signature_bytes` (and any future bytes field) before the dict is merged into the response.

### Verification performed
Ran the real `fastapi.encoders.jsonable_encoder` in the eph pod against a brand dict containing both bytes fields:
- OLD strip (`k != "company_logo_bytes"`) → `UnicodeDecodeError: 'utf-8' codec can't decode byte ... invalid start byte` (reproduces the production error class).
- NEW strip (`not isinstance(v, (bytes, bytearray))`) → **encoded OK**.

### Recommended hardening (optional but advised)
The endpoint's inner try/except cannot catch serialization-time errors because they occur after `return`. To make the endpoint genuinely "never 500", also sanitize the enriched rows before returning (strip any bytes values), e.g. apply the same `isinstance` filter to each row in both the success and fallback branches of `_enrich_payments_bulk` and in `kiosk_tenant_payments`. Consider also having `_company_brand_info` not return raw bytes to list endpoints at all (only for PDF generation).
